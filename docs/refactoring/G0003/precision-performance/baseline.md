## 方法

在同一工作区以 Release 构建运行一次预热和五次采样。中位数用于验收，P95 保留异常样本；分配取五次采样
中位值。场景尺寸、迭代、精度和参考点固定，优化前后结果用同一 SHA-256 短指纹校验。

```powershell
dotnet run --project tools/FractalArtPlugin.Benchmarks -c Release -- `
  docs/refactoring/G0003/precision-performance/optimized-results.json
```

## 结果

| 场景 | 基线中位 ms | 优化后中位 ms | 耗时下降 | 基线分配 | 优化后分配 | 分配下降 | 指纹一致 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| normal-double | 0.262 | 0.219 | 16.4% | 26,168 B | 26,296 B | -0.5% | 是 |
| deep-96 | 109.956 | 2.387 | 97.8% | 226,772,240 B | 478,816 B | 99.8% | 是 |
| deep-256 | 140.975 | 1.913 | 98.6% | 229,897,888 B | 462,504 B | 99.8% | 是 |
| extreme-1024 | 167.877 | 1.651 | 99.0% | 132,241,640 B | 715,688 B | 99.5% | 是 |

旧内核取消响应样本为 133.7 ms；优化后五次样本的 P95 为 2.8 ms，低于 100 ms 指标。normal-double 不属于本专项的高精度验收项，
其亚毫秒输入容易受计时噪声影响，因此不据此宣称加速或回退。

原始样本见 [baseline-results.json](baseline-results.json) 和 [optimized-results.json](optimized-results.json)。
两份 JSON 还包含 P95、GC 次数、进程 CPU 时间、吞吐、有效精度、内核、回退数及四个参考点。

## 口径限制

- 最大迭代吞吐使用“像素数 × 最大迭代数”，不是实际执行迭代计数，只用于同场景比较；
- 采样场景刻意较小，使 1024 位旧参考路径在开发机可完成，不得通过之后缩小输入重新宣称达标；
- 当前数据是本机工程证据，不建立 CI 性能门禁；
- Git 工作树包含专项实施改动，因此优化结果仍绑定起始提交，并由结果 JSON 与本次 diff 共同定位。
