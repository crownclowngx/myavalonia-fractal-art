# G0003 高精度性能与领域模块化专项计划

> 文档状态：已实施，自动化与本机性能指标通过；真实 Host 人工验收待完成
> 计划日期：2026-09-03
> 所属阶段：G0003 第一条 Julia 纵向渲染切片的质量增强，不占用 G0004 产品阶段编号
> 配套设计：[高精度优化与领域模块化设计](optimization-design.md)

## 1. 目标

在不降低作品精度、不改变 v1/v2 文件兼容语义、不破坏渲染确定性的前提下，降低任意精度 Julia 的预览耗时、
内存分配和取消延迟，同时把当前平铺在 `Domain` 根目录的职责整理成清晰的领域模块。

本专项坚持以下顺序：先建立可复现基线，再做无损结构调整，然后实施低风险性能优化，最后才评估扰动算法。
目录移动不能夹带算法变化，性能提升也不能用降低用户声明精度来冒充。

## 2. 首要约束

1. SOLID 仍是第一评审顺位，数值内核不得依赖 Avalonia、Document 或 Host；
2. 采用朴素的策略对象、窄接口和不可变上下文，不引入通用计算图、事件总线或自制依赖注入容器；
3. 公共边界、精度推导、并行调度、取消和回退条件使用详细中文注释说明设计意图；
4. 单元测试验证正确性，性能基准负责测量速度，禁止把易抖动的墙钟时间写进普通单元测试；
5. 不使用 AIFLOW，不增加 Windows CI，不执行发布、安装或 ZIP 门禁；
6. 保持作品格式 v2，不因内部目录和内核调整无必要地升级持久化版本。

## 3. 当前基线判断

当前任意精度路径已经具备固定小数位、预览像素预算、取消和确定性，但尚有以下明确成本：

- 高精度内核单线程逐像素执行；
- 用户配置 1024 位时，即使当前尺度只需要几十位，也会使用完整 1024 位预算；
- 每个像素坐标都执行一次 `BigInteger` 比例乘除，没有利用相邻像素等步长；
- `FixedPoint` 的不可变运算会在热循环产生多个临时 `BigInteger`；
- 取消只在每行开始处检查，极端精度和迭代数下可能出现明显迟滞；
- 拖动期间持续请求真实重算，没有先复用上一帧提供即时视觉反馈；
- `ArtworkDefinition.cs`、`ArbitraryDecimal.cs` 和 `Rendering.cs` 同时承载多类职责，继续扩展会放大修改面。

在采集基准数据以前，只把这些结论视为代码路径分析，不虚构具体毫秒数或加速倍数。

## 4. 工作包与实施顺序

### P01：建立性能与正确性基线

- 新增独立 Release 性能工具，不进入插件交付物；
- 固定普通尺度、96 位深缩放、256 位深缩放和 1024 位极深缩放四组场景；
- 记录预热后的中位耗时、P95 耗时、分配字节、GC 次数、取消响应和结果指纹；
- 保存测试机器、CPU、运行时、尺寸、迭代数、精度、提交号和执行命令；
- 为中心点、边界点、快速逃逸点和高迭代内部点建立参考结果。

产物：`baseline.md` 和机器可读的基准结果。基准只是本地工程证据，不创建 CI 性能门禁。

### P02：Domain 模块化整理

- 按 Artwork、Viewport、Rendering、Fractals/Julia 拆分领域目录与命名空间；
- 把 `ArbitraryDecimal`、二进制定点数和精度换算移动到独立 `Numerics` 支撑模块；
- 把渲染契约、Julia 策略选择和具体内核拆开；
- 镜像整理测试目录；
- 本工作包只做移动、重命名和依赖收敛，结果指纹必须与调整前一致。

产物：结构决策记录、依赖方向检查、全量测试结果。

### P03：动态有效精度

- 将“用户精度上限”和“本次渲染实际精度”区分为两个概念；
- 根据尺度指数、输入有效位、最大迭代数和保护位推导本次有效精度；
- 有效精度不得超过用户配置上限，也不得低于保证当前像素可区分所需的下限；
- `RenderContext` 明确记录请求精度、有效精度和选择原因，状态栏显示真实计算精度；
- 对边界不稳定的结果提升精度重算，不能静默接受可能错误的低精度结果。

产物：独立精度策略、边界测试、与全精度参考结果的差异报告。

### P04：低风险热路径优化

- 每帧预先计算左上坐标和 X/Y 像素步长，相邻像素只执行定点加法；
- 缓存定点舍入常量、逃逸阈值和精度相关参数；
- 把热循环从带重复精度检查的通用值对象调用收敛为内核私有原语；
- 保持十进制解析和作品验证在渲染开始前执行一次；
- 为长循环增加低频但有上界的取消检查。

产物：微基准对比、分配分析和相同上下文的确定性证明。

### P05：有界分块并行

- 按连续行块而不是单像素创建任务；
- 最大并行度默认不超过 `min(逻辑处理器数 - 1, 8)`，至少保留一个响应线程；
- 每个工作块只写自己拥有的数组区间，不共享可变数值状态；
- 首个异常或取消触发全局停止，迟到块不能提交旧 generation；
- 串行与并行模式使用同一像素算法，结果必须完全确定。

产物：并行调度测试、竞争条件检查和不同核心数下的基准报告。

### P06：交互感知的渐进预览

- 拖动和连续滚轮期间先对上一张 Bitmap 做只读视觉变换；
- 输入稳定后再提交低分辨率高精度预览，随后按需提升质量；
- 视觉变换只属于暂态呈现，不能写入作品、导出或结果指纹；
- 任何阶段都服从 Document 的 generation、取消和关闭生命周期。

产物：交互状态测试、人工视觉检查表和取消/迟到测试。

### P07：扰动算法可行性验证

- 高精度计算中心参考轨道，像素使用相对中心的普通浮点扰动；
- 实现误差或 glitch 检测，失败像素必须提升精度或回退到完整任意精度；
- 与完整任意精度内核逐像素对照，不以“看起来相似”作为正确性证明；
- 只有在深缩放基准显示稳定收益后，才决定是否进入默认路径。

P07 是独立决策点，不与 P02–P05 合并提交。

## 4.1 实施闭环

P01–P07 已按顺序完成。P07 的扰动算法仅自动用于任意精度草稿预览；最终导出和显式
`ReferenceArbitrary` 请求仍使用权威定点内核。完整实现、原始数据和验收结论分别见
[实施说明](implementation.md)、[基准记录](baseline.md)和[专项结果](result.md)。

## 5. 验收指标

所有性能比例都在同一台机器、相同 Release 构建、相同输入和相同运行时下与 P01 基线比较：

- 96 位和 256 位预览中位耗时至少降低 50%；
- 1024 位预览中位耗时至少降低 30%；
- 取消请求到计算停止的 P95 不超过 100 ms；
- 高精度热路径的每帧托管分配至少降低 30%；
- 串行与并行内核对同一有效上下文产生一致的逃逸掩码和标量场；
- 动态精度结果与全精度参考之间不得出现逃逸分类差异，标量误差满足专项设计定义的容差；
- 拖动和滚轮输入后应立即得到复用帧反馈，真实渲染仍不得提交过期结果；
- v1 迁移、v2 往返、撤销/重做和 PNG 导出语义保持不变；
- 全量构建零警告，全部单元测试、格式检查和 Standalone 烟雾验证通过。

如果硬件无法达到目标，结果文档必须保留原始数据并说明瓶颈，不能通过缩小基准输入宣称达标。

## 6. 测试矩阵

- 精度策略：普通尺度、阈值上下、最大有效位、保护位不足和配置上限不足；
- 数值内核：中心、边界、内部、快速逃逸、极小尺度和极端迭代数；
- 并行：1/2/多工作线程、非整除块高度、异常、取消和重复运行；
- 生命周期：连续拖动、连续滚轮、关闭、旧 generation 迟到和导出取消；
- 兼容：v1 → v2、v2 完整往返、未知版本、恶意指数和资源预算；
- 架构：Domain/Numerics 不引用 Avalonia、Features 或 Host 实现。

## 7. 提交建议

为降低评审风险，建议至少拆成以下提交：

1. `refactor: 模块化 Fractal Art 领域与数值目录`；
2. `perf: 引入动态有效精度与高精度坐标增量`；
3. `perf: 增加任意精度分块并行和快速取消`；
4. `feat: 增加交互渐进预览`；
5. `docs: 记录高精度性能基准与实施结果`。

扰动算法若实施，应使用独立提交和独立结果文档。
