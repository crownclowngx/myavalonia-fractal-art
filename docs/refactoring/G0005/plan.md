# G0005 当下计划：第二类数据形态——递归路径

## 目标

在现有 Julia 标量场之外增加“递归树 → 路径几何 → 描边 → 图像面”的完整纵向链路，证明作品模型、
Document、变体、保存和导出没有被第一种像素数据形态绑死。生成阶段必须保留矢量和层级语义，
不能为了快速显示而提前变成位图。

## 首要工程约束

1. SOLID 是实现评审第一顺位：领域路径不依赖 Avalonia，Document 不识别具体路径算法；
2. 设计模式朴素使用，只用生成器渲染策略与窄端口，不建设通用节点图、事件总线或插件式公式框架；
3. 公共边界、预算、确定性、迁移和取消必须有详细中文注释；
4. 单元测试覆盖算法、资源边界、变体、持久化、Document 复用、取消及真实渲染结果；
5. 同步产品基线、质量门禁、快速开始和阶段档案；
6. 不使用 AIFLOW，不新增 Windows CI，不执行部署、发布或正式 ZIP 门禁。

## 工作项

1. 增加稳定的 `FractalGeneratorKind` 与 `RecursiveTreeDefinition`，作品格式升级到 v4；
2. 定义独立于 UI/像素的 `PathPoint`、`PathSegment`、`PathGeometry`，每段保留递归层级；
3. 实现固定随机算法的递归树路径生成器，并限制深度、分叉和总线段数；
4. 实现颜色随层级插值、线宽随层级衰减的 CPU 路径描边器；
5. 用窄渲染策略让 Julia 和递归树共用预览、九宫格、PNG 导出与取消管线；
6. 将递归层级、分叉、角度、长度衰减和随机度接入确定性变体；
7. 增加“无限与花朵”“植物与生长”两个视觉入口及递归树参数界面；
8. v1/v2/v3 显式迁移到 v4，旧作品和旧候选固定迁移为 Julia；
9. 补齐 Debug/Release 构建、测试、格式及 Standalone 启动烟雾验证。

## 完成标准

- 路径生成结果仍是带层级的线段结构，描边前不存在像素缓冲区；
- 相同 Seed 和配方逐段相同，不同 Seed 在随机度非零时产生不同路径；
- 深度为 1–12、分叉为 2–3，任意合法组合的总线段数不超过 50,000；
- 预览与 PNG 导出使用同一个递归路径渲染策略；
- 树变体始终保持当前生成器，且每个候选重新通过统一作品验证器；
- v4 保存树配方、候选和收藏，v1/v2/v3 不静默猜测第二种生成器；
- Julia 与递归树共用同一个 `FractalArtworkDocument`，不复制历史、Dirty、取消或保存基础设施；
- 本地自动化门禁全部通过，未完成的真实 Host 与视觉检查如实列出。

## 明确不做

- 不提前实现 G0006 节点图、缓存失效图或通用效果链；
- 不在本阶段实现 SVG 文件导出，只保留可直接消费的矢量路径语义；
- 不增加 L-System 文本规则编辑器、递归圆或更多公式；
- 不增加 Tool、Workbench Command、菜单或默认快捷键；
- 不使用 AIFLOW，不新增 Windows CI，不执行部署、发布或正式 ZIP 门禁。
