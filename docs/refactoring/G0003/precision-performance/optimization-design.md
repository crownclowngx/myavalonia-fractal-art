# 高精度优化与领域模块化设计

> 文档状态：已实施；扰动算法仅用于草稿预览自动路径，最终导出保留权威内核
> 配套计划：[G0003 高精度性能与领域模块化专项计划](plan.md)

## 1. 决策摘要

当前 `BigInteger` 定点 Julia 内核适合作为正确性参考和安全回退，但不应直接承担所有像素、所有迭代和所有
用户配置位数。目标架构保留这条权威路径，同时依次增加动态有效精度、坐标增量、有界分块并行和渐进预览。
扰动算法作为后续可选策略，必须带有错误检测和完整高精度回退。

目录结构采用模块化单体。Artwork、Viewport、Rendering 和 Fractals/Julia 是同一产品领域中的能力模块，
不是独立部署的限界上下文；Numerics 是支撑计算的技术核心，不伪装成业务子领域。

## 2. 性能模型

设预览像素数为 `P`，平均迭代次数为 `I`，定点位数为 `B`。当前热路径近似执行：

```text
P × I ×（3 次大整数乘法 + 多次大整数加减与舍入）
```

`B` 随十进制精度近似按 `ceil(decimalDigits × log2(10)) + guardBits` 增长。96 位约对应 335 个带保护位的
二进制小数位，1024 位约对应 3418 个带保护位的二进制小数位。大整数乘法成本会随位数非线性增长，
因此简单降低预览分辨率只能控制总工作量，不能解决不必要的超额精度和重复坐标除法。

当前主要浪费点如下：

1. 配置精度被直接当作每次渲染精度；
2. 每个像素从中心、尺度和比例重新计算坐标；
3. 单线程无法使用多个 CPU 核心；
4. 通用不可变定点值对象在内层循环重复校验精度并创建临时值；
5. 交互期间每个稳定窗口都重新计算画面，无法立即反馈。

### 3.1 依赖方向

```text
Features → Application → Domain
                         ├─ Artwork
                         ├─ Viewport
                         ├─ Rendering contracts
                         └─ Fractals/Julia → Numerics
```

- `Numerics` 只能依赖 BCL；
- `Domain` 不依赖 Avalonia、Document、文件系统或 Host；
- `Application` 编排渲染、快照和导出，不包含复数公式；
- `Features` 处理指针输入和 Bitmap 呈现，不决定数值精度；
- 具体 Julia 内核实现同一窄接口，选择器不读取 UI 控件。

## 4. 精度策略

### 4.1 区分三个概念

- **配置精度**：用户允许作品使用的最大十进制有效位，继续随 v2 作品保存；
- **所需精度**：根据当前尺度、输入有效位和数值稳定性估算；
- **有效精度**：本次 RenderContext 实际采用的精度，不超过配置精度。

初始策略可采用以下保守模型，最终保护位由基准和对照测试校准：

```text
scaleDigits      = max(0, -scale.AdjustedExponent)
parameterDigits  = max(中心、尺度、Julia 常量的有效位)
iterationGuard   = 与最大迭代数相关的保护位，且设最小值
requiredDigits   = max(32, scaleDigits + iterationGuard, parameterDigits)
effectiveDigits  = min(configuredDigits, requiredDigits)
```

如果 `requiredDigits > configuredDigits`，领域验证或渲染请求必须明确报告“配置精度不足”，不能静默截断。
用户勾选“强制高精度”只决定禁用 `double` 快速路径，不等于无条件使用全部配置位数；如需诊断完整精度，
应另设开发级策略而不是复用用户开关。

### 4.2 稳定性回退

动态精度内核遇到以下情况之一时提升精度或回退到配置精度：

- 逃逸幅值距离阈值 4 落入误差保护区；
- 两档精度计算得到不同逃逸分类；
- 平滑迭代值包含非有限数或超出 0..1；
- 扰动量超过参考轨道允许范围；
- 精度策略无法证明相邻像素仍可区分。

回退属于正确性机制，必须记录在诊断结果中，但不写入作品持久状态。

## 5. 内核优化

### 5.1 坐标增量

每帧只计算一次像素步长：

```text
pixelStep = scale / viewportHeight
left      = centerX - (width - 1) × pixelStep / 2
top       = centerY - (height - 1) × pixelStep / 2
```

同一行内通过 `real += pixelStep` 前进，下一行通过 `imaginary += pixelStep` 前进。这样可把每像素一次
`BigInteger` 乘除变为定点加法。为了避免累计舍入漂移，每个分块从自己的绝对起始坐标计算一次，而不是跨越
整幅画面持续累加。

### 5.2 内核私有定点原语

`ArbitraryDecimal` 继续负责作品输入、持久化和视口几何；Julia 热路径使用内核私有的二进制定点表示。
定点上下文预先保存：

- 小数位数；
- 乘法舍入常量；
- 逃逸阈值；
- 像素步长；
- `c.real` 与 `c.imaginary`；
- 取消检查间隔。

公共数值类型保持安全验证，热路径只接受已经由上下文验证过的同精度操作数，从而避免每次加减再次检查。
除非基准证明有必要，不实现自制大整数或对象池；BCL `BigInteger` 仍是首选正确性基础。

### 5.3 有界并行

渲染器把图像拆成固定高度的连续行块。每个块拥有独立坐标和局部数值变量，只写最终数组的专属区间。
调度器接受显式最大并行度，默认：

```text
maxDegree = max(1, min(Environment.ProcessorCount - 1, 8))
```

这个上限避免插件占满 Host 全部工作线程。最终数组的位置由像素坐标决定，调度顺序不参与计算，因此不同线程
完成顺序不能改变结果。不得在像素热循环内创建 Task。

### 5.4 取消

每个分块开始、每行开始以及固定像素/迭代间隔检查取消。检查间隔由上下文常量控制，在取消响应和分支成本之间
取得平衡。取消后停止领取新块；已经运行的块尽快退出；Document 仍以 generation 检查阻止迟到结果提交。

## 6. 渐进交互

输入层和真实渲染分成两条时间线：

```text
指针移动
  → 立即变换上一张预览 Bitmap（暂态、不可导出）
  → 合并短时间内的连续输入
  → 提交低成本真实预览
  → 输入稳定后提交较高质量真实预览
```

暂态 Bitmap 变换只改变 View 的呈现矩阵。作品中心和尺度仍由 `HighPrecisionViewport` 精确更新；保存、撤销、
指纹和 PNG 导出只能使用作品快照与真实渲染结果。这样提升的是感知延迟，不会用插值图片冒充最终计算。

## 7. 扰动算法

对中心参考轨道：

```text
Z(n+1) = Z(n)² + c
```

像素与参考点的差值满足：

```text
δ(n+1) = 2 × Z(n) × δ(n) + δ(n)²
```

参考轨道使用任意精度计算一次，大量像素主要用 `double` 或扩展浮点计算 `δ`。这可能带来数量级收益，
但必须处理参考轨道过小、差值放大、下溢、取消和 glitch 像素。设计要求：

- 完整任意精度内核始终保留为参考和回退；
- 每个像素具有明确的误差检测，不允许只依靠肉眼比较；
- glitch 像素可提升精度、重新选择参考点或回退完整内核；
- 扰动内核失败不能导致整帧静默错误；
- 未通过极端边界对照前，不成为默认导出路径。

因此扰动算法属于第二层优化，不阻塞动态精度、坐标增量和并行化交付。

## 8. 正确性与性能验证

### 8.1 正确性

- 固定输入重复运行的结果完全一致；
- 串行和并行结果完全一致；
- 动态精度与配置全精度参考的逃逸掩码一致；
- 标量场误差使用明确容差比较，并额外覆盖逃逸阈值附近样本；
- 发生不稳定时能够观察到精度提升或回退；
- 导出不使用暂态 Bitmap；
- 作品 JSON 不保存有效精度、线程数或临时预览状态。

### 8.2 性能

性能工具使用 Release 构建、预热、多次运行和结果校验，至少输出：

- 中位耗时与 P95；
- 每秒像素数和每秒有效迭代数；
- 当前线程数与 CPU 使用率；
- 每帧分配字节和 GC 次数；
- 取消响应时间；
- 渲染结果指纹。

性能结果必须与机器信息和 Git 提交绑定。普通单元测试不设置毫秒级断言，避免不同开发机产生伪失败。

## 9. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 动态精度过低导致边界像素错误 | 保护位、双精度档对照、阈值检测和全精度回退 |
| 并行化造成 Host 卡顿 | 保留一个逻辑核心、最大 8 路、支持显式调度预算 |
| 坐标累加产生漂移 | 每个分块从绝对起点计算，建立锚点与对称性测试 |
| 目录重构混入行为变化 | P02 独立提交，重构前后指纹和全量测试一致 |
| 暂态预览被误当作成品 | 类型和状态明确区分，保存/导出管线只接受真实渲染结果 |
| 扰动算法局部失真 | glitch 检测、逐像素参考对照和完整内核回退 |
| 性能优化制造复杂框架 | 每个抽象必须对应已存在变化点，禁止预建通用节点系统 |

## 10. 暂不采用

- 不直接在 GPU 上实现通用 1024 位大整数；
- 不自行实现大整数乘法库；
- 不通过降低最终导出尺寸宣称加速；
- 不缓存没有明确失效规则的全局可变结果；
- 不把并行度、有效精度或机器特征写入作品文件；
- 不在本专项引入 Mandelbrot、多图层、效果链或 G0004 变体功能。
