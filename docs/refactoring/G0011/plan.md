# G0011：静态作品闭环封板计划

## 产品结论

在现有五类生成器、变体、多图层、效果、数学透镜和 v8 持久化之上，补齐工作区状态、会话态导出配置、
透明/高分辨率 PNG、缺失能力显式修复、固定迁移夹具及多数据形态性能证据，形成首个静态作品本地闭环。

## 首要约束

- SOLID 是第一评审顺位：状态、兼容检查、导出规划、编码、文件事务和 View 分责；
- 只使用不可变值对象、窄端口和既有策略管线，不建设事件总线、通用节点框架或额外容器；
- 保持 Content schema 1、Artwork v8、renderer v1、Plugin/Document ID、SDK 区间和 `1.0.0` 不变；
- 缺失能力必须无损保存并失败关闭，只有用户明确操作才能删除，且删除可撤销；
- 导出尺寸和透明背景是 Document 会话态，不进入作品、Dirty、历史或数学透镜；
- 不使用 AIFLOW，不新增 Windows CI，不执行 Release、部署、ZIP、签名、安装或发布门禁。

## 完成标准

- Loading、Ready、Blocked、Failed 状态及新建作品快速开始可明确区分；
- 自定义尺寸、等比锁定、透明背景、最终质量和原子 PNG 导出形成闭环；
- 预览、缩略图和导出复用同一作品/合成/Alpha/色彩语义；
- v1–v8 固定夹具全部迁移，未知能力可无损往返、阻止输出并显式修复；
- 本地 Debug 构建、单元测试、格式门禁和 Standalone 烟雾通过；
- 正式 ZIP、干净部署和真实 Host 验收如实留到发布阶段。
