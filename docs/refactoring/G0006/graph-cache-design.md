# G0006 创作图与缓存设计

## 设计原则

创作图只解决作品内部的局部求值，不是 Host Workflow Action，也不是面向用户的节点语言。参数继续由
`ArtworkDefinition` 的强类型记录唯一持有；图只保存节点身份、操作版本、端口和连接，避免出现图参数与作品参数两份事实。

```text
Julia / Mandelbrot ─→ ScalarField ─→ ScalarGradient ─┐
                                                     ├→ EffectChain → Composition → Output
Tree / L-System ────→ PathGeometry ─→ PathStroke ───┘
```

G0006 的效果链为空，单层合成保持现有像素不变。路径描边继续在自身阶段应用背景，以保证旧作品指纹；透明图层和
真正的多层合成留给 G0008。

## 类型安全和验证

每个操作都有固定版本、必需输入端口和唯一输出端口。图验证按以下顺序执行：

1. 检查图、效果链、节点操作及节点版本；
2. 检查节点 ID、输出节点和与当前 `GeneratorKind` 匹配的唯一生成节点；
3. 检查连接端点、端口名、数据类型及每个必需输入恰好连接一次；
4. 使用稳定的 Kahn 排序拒绝循环；
5. 从生成节点遍历，拒绝未连接到生成—输出主链的节点。

诊断保存稳定代码、可选节点 ID 和详细中文消息。执行期异常再由 `ArtworkGraphExecutionException` 补充节点操作，
使恢复损坏作品与算法运行失败能够清楚区分。

## 不可变数据

`ScalarField`、`ImageSurface` 和 `Mask` 在公共构造时防御性复制输入，并只暴露 `ReadOnlyBuffer<T>`；内部数值内核
通过所有权移交入口避免重复复制。`PathGeometry` 继续在构造时复制线段。节点缓存因此可以安全共享同一输出引用，
效果实现也不能原地修改上游结果。

## 缓存身份

每个节点键先用带长度前缀的二进制格式写入图版本、节点 ID、操作/节点版本、渲染器版本和有序上游摘要，再显式写入
该节点真正读取的参数，最后计算 SHA-256：

- 逃逸时间生成节点：公式定义、尺寸、质量、精度和内核偏好；
- 路径生成节点：几何参数，递归树额外包含 Seed，但不包含尺寸、质量、渐变或线宽；
- 标量着色节点：上游摘要和渐变；
- 路径描边节点：上游摘要、渐变、背景、线宽、尺寸和质量；
- 效果、合成和输出边界：上游摘要及各自版本/定义。

这种内容寻址不需要主动遍历删除下游：参数改变后相关节点自然获得新键，仍有效的上游键继续命中；旧项随后由 LRU 淘汰。

## 容量、并发和取消

- 每个 Document Scope 默认最多 128 MiB、256 项；任一条件超限都从最久未使用项开始淘汰；
- 单项超过总字节预算时照常执行但不缓存，避免高分辨率导出挤掉整个交互缓存；
- 锁只保护字典和 LRU 链表，不包围计算；相同冷请求可以重复计算，取消互不传播；
- 节点成功后再次检查取消令牌，只有仍有效的完整结果才能写入；
- 执行摘要分别记录命中和实际执行节点，属于运行态诊断，永不进入作品文件。

## SOLID 落点

| 原则 | G0006 落点 |
| --- | --- |
| 单一职责 | 图定义、验证/排序、键生成、LRU、节点算法、Document 提交和快照分别实现 |
| 开闭原则 | 新节点通过显式操作、描述和执行器追加；Document、导出器和预览无需识别算法类型 |
| 里氏替换 | 生产执行器与测试替身遵守同一输入、取消和不可变输出契约 |
| 接口隔离 | 图验证、图执行、缓存、渲染管线和算法端口相互独立 |
| 依赖倒置 | 应用执行器依赖领域算法端口和缓存端口，不直接依赖 Avalonia 或文件系统 |

采用的模式仅为策略、规范工厂、cache-aside 和 LRU；没有引入反射注册、事件总线、仓储、Visitor 或通用工作流框架。
